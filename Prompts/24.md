## Tarefa — Otimização de performance e fluidez

**Arquivos alvo:** todos os arquivos do projeto (somente leitura inicial)

---

### Regras invioláveis

- ANALISE antes de alterar — nenhuma linha de código deve ser modificada
  antes de concluir o diagnóstico completo.
- NÃO instale dependências novas.
- NÃO crie componentes, hooks ou utilitários novos sem justificativa
  direta em um gargalo identificado.
- NÃO altere layout, estilização, lógica de dados ou comportamento visual.
- MANTENHA a essência e arquitetura existente do projeto.
- APLIQUE apenas mudanças com impacto direto e mensurável em performance.

---

### Etapa 1 — Diagnóstico obrigatório (não pule esta etapa)

Percorra os arquivos abaixo e registre o que encontrar antes de alterar
qualquer coisa:

**1.1 — Renderizações desnecessárias**

- Identifique componentes que re-renderizam sem mudança de props ou estado.
- Verifique se `useEffect` tem dependências corretas ou está rodando em loop.
- Verifique se objetos ou funções são recriados a cada render sem `useMemo`
  ou `useCallback`.

**1.2 — Atualizações em tempo real**

- Localize todos os `setInterval`, `setTimeout` e WebSocket listeners.
- Registre a frequência de atualização de cada um (ex: a cada 500ms, 1s, 5s).
- Identifique se algum está atualizando estado global desnecessariamente,
  causando re-render em cascata.

**1.3 — Scroll e layout**

- Verifique se há listeners de `scroll` ou `resize` sem `passive: true`.
- Identifique animações CSS usando `top/left/width/height` em vez de
  `transform/opacity` (causam reflow).
- Verifique se há elementos com `overflow` mal configurado travando o scroll.

**1.4 — Componentes pesados**

- Identifique gráficos (Recharts, Chart.js) que re-renderizam a cada tick
  de dados em tempo real.
- Verifique se imagens têm `width` e `height` definidos para evitar CLS.

### Etapa 3 — Aplicação das correções

Aplique apenas as correções aprovadas no plano, seguindo esta ordem de
prioridade:

**Prioridade 1 — Memoização**

- Envolva com `React.memo()` componentes filhos que recebem as mesmas props
  a cada render do pai.
- Use `useCallback` em handlers passados como props para componentes filhos.
- Use `useMemo` em cálculos derivados de dados que não mudam a cada tick.

**Prioridade 2 — Throttle em atualizações em tempo real**

- Se intervalos de atualização forem menores que `1000ms`, avalie aumentar
  para `1000ms` ou `2000ms` sem perda funcional.
- Separe estado de UI (ex: animações) do estado de dados para evitar
  re-renders desnecessários no restante da árvore.

**Prioridade 3 — Scroll fluido**

- Adicione `passive: true` em event listeners de scroll e resize.
- Substitua animações com `top/left` por `transform: translateY/translateX`.
- Garanta `will-change: transform` apenas em elementos que realmente animam
  de forma contínua.

**Prioridade 4 — Lazy loading**

- Componentes pesados (gráficos, tabelas grandes) devem usar
  `React.lazy()` + `Suspense` se ainda não estiverem.
- Verifique se o Next.js já aplica code splitting automático nas rotas —
  não duplique o que o framework já faz.

---

### O que NÃO fazer

- NÃO adicione `React.memo` indiscriminadamente — apenas onde o diagnóstico
  confirmou re-render desnecessário.
- NÃO altere a frequência de atualização de dados sem validar que o
  comportamento em tempo real não será prejudicado.
- NÃO mova lógica de componentes para fora sem entender suas dependências.
- NÃO altere estilização, cores, layout ou comportamento visual.
- NÃO refatore código funcional que não está relacionado a performance.
